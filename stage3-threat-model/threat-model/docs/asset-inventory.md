**Source of truth:** built from `stage2/.../docs/architecture.md`,
`network-design.md`, `security-hardening.md`, and `stage1/src/` + `stage1/outputs/`.
**Rule:** an asset's *data/sensitivity* here must match the owning stage's
docs — if they disagree, fix the stage doc, not this file.

Legend — **C** = confidentiality, **I** = integrity, **A** = availability
(CIA triad) · **Value** = what it is worth to the lab narrative.

## C. Asset inventory rules

1. **Add before you build:** every new module adds its assets here *first*.
2. **One owner:** each asset has exactly one owning stage (the stage that
   creates it); consumers are recorded in the DFD instead.
3. **Sensitivity is stage-relative:** A-16 (Kali) is *trusted in-lab* — its
   confidentiality matters (attacker tools/keys), but it is not a target of
   the model's own attackers.
4. **Never store secrets:** consistent with `lab.env`, no credential value
   ever appears in this inventory.
